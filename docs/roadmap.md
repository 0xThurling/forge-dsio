# Roadmap

Build order follows one rule: **never implement a file before the files it
depends on exist**. Each stage has a deliverable, tests, and a gate. Do not
start the next stage until the gate passes.

Legend: `[ ]` todo, `[~]` in progress, `[x]` done. Keep this file updated as
the project progresses.

## Stage 1 — Buffers and files (done)

Files:

- [x] `fp::AlignedBuffer` in ForgeFP's `memory.hpp` — runtime-aligned byte
      block (power-of-two alignment, size rounded up, move-only) with fp tests
      and `.docs/memory.md`; the installed mirror is regenerated by `forge build`
- [x] `include/dsio/file.hpp` + `src/file.cpp` — `File` RAII fd:
      `open(path, OpenMode)`, `size()`, `pread`/`pread_exact`,
      `pwrite`/`pwrite_exact`, `sync()`, and the file's `alignment()` recorded
      at open
- [x] `test/direct_io_fixture.hpp` — O_DIRECT probe (skips, or fails with
      `DSIO_REQUIRE_DIRECT=1`) and a per-test directory under `build/test-data/`
- [x] `test/file_test.cpp` — direct round-trip, alignment errors, empty file,
      tail, direct write

ForgeFP usage: `fp::Outcome`/`fp::error`, `fp::AlignedBuffer`, `fp::io`
(`write_bytes` to create fixtures, `read_bytes` as the reference).

Tests: allocation alignment; O_DIRECT round-trip byte-identical to a buffered
read; misaligned offset/buffer/length → `EINVAL` as a value; missing file →
error; empty file reads 0 bytes; the tail is a short read at EOF;
`pwrite` + `sync` round-trip.

Gate: byte-identical direct read; every failure is a value; suite green on
ext4 with the probe reporting O_DIRECT support. **Met** — 16/16 tests on
WSL2/ext4. Finding: the kernel's real requirement is the device *logical*
block size (512 here), while `alignment()` conservatively returns the
filesystem block size (4096); a 2048-byte request is accepted, an odd one is
`EINVAL`.

## Stage 2 — DirectReader (done)

Files:

- [x] `include/dsio/reader.hpp` + `src/reader.cpp` — `DirectReader`:
      synchronous baseline; block buffer sized from the file's alignment,
      `next_chunk()` → `fp::Outcome<Chunk>` (`Chunk` = span + file offset),
      the tail is the short read at EOF, `reset()` / `position()`
- [x] `test/reader_test.cpp`

ForgeFP usage: `fp::Outcome`, `fp::AlignedBuffer`, `fp::io` (`read_bytes` as
the reference).

Tests: contents equal a buffered read for sizes {0, 1, block−1, block,
block+1, 16 MiB}; chunk offsets chain to the file size; the last chunk is the
100-byte tail; chunks reuse one buffer; reset re-reads identically; a missing
file is an error.

Gate: full-file equality at every size; one block buffer per reader (the
synchronous baseline; the async backend brings more buffers in Stage 3).
**Met** — 22/22 tests.

## Stage 3 — Async backend (done)

Files:

- [x] `include/dsio/backend.hpp` — `Backend` interface: `submit(requests)`,
      `reap(out, min)`, `in_flight()`, `queue_depth()`, `name()`; `ReadRequest`
      and `Completion` carry a caller token
- [x] `src/uring.cpp` — io_uring backend (liburing, batched CQE draining) and

- [x] `src/thread_backend.cpp` — fallback: `fp::ThreadPool` + `pread`
- [x] `test/backend_test.cpp` — the same batch contract against both backends,
      plus queue-full, short tail and polling cases
- [x] `bench/read_bench.cpp` — block-size sweep and queue-depth sweep for
      io_uring and the thread fallback (Google Benchmark, real time)

Decided: liburing via `pkgconfig = { "liburing" }`; benchmarks with Google
Benchmark (`testing = { enabled = true, framework = "gtest", benchmark = true }`)
so `forge bench --save/--compare/--fail-over` work.

ForgeFP usage: `fp::ThreadPool`, `fp::Outcome`, `fp::AlignedBuffer`.

Tests: a batch of reads lands correctly on both backends; a queue depth > 1
keeps the device busy; the factory falls back when the ring cannot be created;
`DSIO_REQUIRE_IO_URING=1` turns an unavailable ring into a failure.

Gate: identical results from both backends; benchmark table below. **Met** —
28/28 tests; io_uring works on this WSL2 kernel (`io_uring_disabled = 0`).

## Stage 4 — Shards and the dataset pipeline (done)

Files:

- [x] `include/dsio/mmap.hpp` + `src/mmap.cpp` — read-only `MmapFile`:
      page-aligned windows, `advise` / `prefetch` / `drop` (madvise)
- [x] `include/dsio/shard.hpp` + `src/shard.cpp` — `Shard` (path, offset,
      length), `ShardSet`, TSV manifest (`path<TAB>offset<TAB>length`, decimal
      u64, block-aligned offsets, relative paths resolved against the
      manifest), directory discovery
- [x] `include/dsio/dataset.hpp` + `src/dataset.cpp` — `for_each_batch`: a
      worker over `fp::Channel` reads `prefetch` batches ahead; batch buffers
      are reused (bounded at `prefetch + 1`), batches may span shards, only the
      last is short; `fp::Rng` shuffles the shard order for a nonzero seed
- [x] `DirectReader::open(path, offset, length)` — a window of a file, for
      shards that start inside one
- [x] `test/mmap_test.cpp`, `test/shard_test.cpp`, `test/dataset_test.cpp`

ForgeFP usage: `fp::Channel`, `fp::ThreadPool`, `fp::Rng`, `fp::Outcome`,
`fp::AlignedBuffer`.

Tests: manifest round-trip, malformed lines, misaligned offsets, discovery
sorted with hidden and empty files skipped; mmap windows, alignment and hints;
the pipeline emits every byte exactly once in order, prefetch depth does not
change the stream, buffers are reused (≤ `prefetch + 1`), a seed is
reproducible, the callback can stop early, a missing shard is an error.

Gate: stream a multi-shard dataset with fixed memory; the bytes match the
concatenated shards. **Met** — 51/51 tests.

## Environment notes (this machine)

- WSL2, kernel `6.18.33.1-microsoft-standard-WSL2`; io_uring is not disabled
  (`/proc/sys/kernel/io_uring_disabled = 0`) — still probe at run time and keep
  the fallback first-class.
- Root filesystem ext4 (`/dev/sdd`, logical block 512, `statfs` 4096); `/tmp`
  is tmpfs, which does **not** support `O_DIRECT`.
- liburing 2.15 with headers and pkg-config is installed.
- O_DIRECT works here, including short reads at EOF (Stage 1 verified it).

## How a stage is worked

1. Write the test list first, from the gate.
2. Implement file by file, in the order listed; run `forge test` after each.
3. `forge format` and `forge lint` before the stage is done.
4. Record benchmark numbers for anything hot (Stage 3+); update the table
   below.
5. `forge workspace build` at the end of any stage that touches `fp` or `ml`.

## Benchmark log

256 MiB file, O_DIRECT, WSL2/ext4 (`/dev/sdd`, logical block 512), 12 vCPUs,
`forge bench` with Google Benchmark (real time).

| Date | Stage | Workload | Backend | Throughput | Notes |
|---|---|---|---|---|---|
| 2026-09-24 | 3 | sequential, 4 KiB blocks | `File::pread` | 35 MiB/s | latency-bound: 65 536 serialized reads |
| 2026-09-24 | 3 | sequential, 64 KiB blocks | `File::pread` | 396 MiB/s | |
| 2026-09-24 | 3 | sequential, 1 MiB blocks | `File::pread` | 1.79 GiB/s | |
| 2026-09-24 | 3 | queued 1 MiB, depth 1 | io_uring | 1.71 GiB/s | |
| 2026-09-24 | 3 | queued 1 MiB, depth 4 | io_uring | 2.10 GiB/s | |
| 2026-09-24 | 3 | queued 1 MiB, depth 16 | io_uring | 2.42 GiB/s | |
| 2026-09-24 | 3 | queued 1 MiB, depth 64 | io_uring | 2.65 GiB/s | queue depth still pays |
| 2026-09-24 | 3 | queued 1 MiB, depth 4 | thread (2 workers) | 2.22 GiB/s | |
| 2026-09-24 | 3 | queued 1 MiB, depth 64 | thread (2 workers) | 2.27 GiB/s | saturates around depth 4 |

Takeaway: small sequential O_DIRECT reads are latency-bound (35 MiB/s at
4 KiB), which is what the queued backends exist for; io_uring scales with
queue depth, the thread fallback saturates with its two workers.
